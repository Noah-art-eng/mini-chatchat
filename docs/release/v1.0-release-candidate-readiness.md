# Mini ChatChat v1.0.0-rc.1 Release Candidate Readiness

## Verdict

Mini ChatChat `v1.0.0-rc.1` is ready for a controlled public demo deployment after real production secrets, OAuth callback URLs, and HTTPS domain configuration are supplied.

It is not yet a fully hardened multi-node SaaS deployment. The remaining gaps are operational hardening items, not missing core product features.

## Release Scope

This release candidate validates the current product as a deployable AI SaaS demo:

- React product UI with Chat, Knowledge, Agent, Tool Center, System, Account, login, registration, OAuth entry points, and onboarding.
- Local KB, temp KB, search mode, Agent tools, MCP adapters, conversation history, feedback, sources, import/export, and retrieval debug.
- Email authentication, HttpOnly refresh cookie, session management, user data isolation, account profile, Google/GitHub OAuth infrastructure, and protected capabilities.
- Docker production runtime, nginx frontend, API proxy, health checks, backup/restore scripts, and deployment documentation.

No new RAG, Agent, MCP, Tool Registry, authentication, or API product features were added during this release-candidate pass.

## Release Fixes

### Production API Base

The Docker frontend initially called the development fallback API base. In production this made the UI show stale runtime metadata and would have broken public deployment behind nginx.

Fix:

- `frontend-react/src/api/client.ts` now defaults to `/api` outside Vite dev ports.
- Vite dev ports still default to `http://127.0.0.1:8000` for local development unless `VITE_API_BASE_URL` is provided.

### Dependency Security

The previous React Router dependency path had active advisories. The application only required a small subset of routing primitives, so it now uses an internal minimal router.

Fix:

- Removed `react-router-dom`.
- Added `frontend-react/src/router.tsx`.
- Updated app, auth pages, top bar, and onboarding tests to use the internal router.
- `npm audit` and `npm audit --omit=dev` now report 0 vulnerabilities.

### Public Health Details

Production dependency health previously exposed more runtime detail than needed for a public endpoint.

Fix:

- `/health/deps` always returns status and dependency checks.
- Runtime/model/stat details are only exposed when `HEALTH_DEPS_PUBLIC_DETAILS=true`, or in production to an authenticated user with Developer Mode permission.

### Backup And Restore Guardrails

Backup and restore scripts now include safer release behavior.

Fix:

- Backups generate a `.sha256` checksum.
- Restore verifies the checksum when present.
- Restore requires explicit confirmation unless `RESTORE_CONFIRM=yes` is set for automation.

## Security Notes

Verified:

- Auth cookie uses HttpOnly, Secure, and SameSite.
- Unknown Origin is rejected for sensitive auth requests.
- Public health dependency response is reduced by default.
- No obvious secrets appeared in recent backend logs or tested responses.
- `.env.production.example` documents strict production settings without real secrets.

Still required before internet exposure:

- Configure real `JWT_SECRET_KEY`.
- Configure real DeepSeek or OpenAI provider credentials.
- Configure real Google/GitHub OAuth credentials and callback URLs.
- Serve only over HTTPS.
- Set production `ALLOWED_ORIGINS` to the real domain.
- Keep `COOKIE_SECURE=true`.
- Keep `HEALTH_DEPS_PUBLIC_DETAILS=false` unless a private admin surface is used.

## Known Limitations

- Backend image is still large at about `2.03GB`; main contributors are PyTorch, sentence-transformers, FAISS, SciPy, and scikit-learn.
- Python/container vulnerability scanning is documented but not automated in CI.
- Real Google/GitHub OAuth callbacks were not verified against live provider credentials in this local run.
- Production compose is single-host SQLite oriented; this is acceptable for a public demo but not a horizontally scaled SaaS.
- Backup archives are local and not encrypted by default.
- Off-host backup storage and log rotation remain operator responsibilities.
- OAuth state/session storage is suitable for this single-instance deployment model; multi-instance deployment would need shared state.

## Final Decision

Status: `APPROVED FOR PUBLIC DEMO RC`

Mini ChatChat is production deployable for a controlled single-host public demo after real environment secrets and HTTPS are configured. It should not yet be marketed as a fully hardened enterprise SaaS until image optimization, CI security scanning, live OAuth validation, encrypted off-host backups, and operational monitoring are completed.
